1. Scope and design principles

What RODBOT is [A]
  • A read-only checker beside Command QC. It never writes quotes or prices.
  • Reproduces Rod's checks: 3 exception reports, plant feasibility, quote expiry and supplier price-rise alerts, margin vs 20-22% Adbri target, plus a step-owner register.
  • Replicate first, redesign later. Managers keep the pricing decision.
Priority order [A]
  1. Step ownership (criterion 4) and exception reports (criterion 1)
  2. Plant feasibility (criterion 2)
  3. Expiry and price-rise alerts (criterion 3)
  4. Margin flag (criterion 5)
Out of scope for release 1 [A]
  • Replacing Command QC, writing back to it
  • Plants other than Echuca
  • Process redesign, pipeline of unconfirmed work
  • Command QC API integration (optional task W1-7, only if Daryl approves)

2. Assumed technical approach (confirm via Q4, Q5)

Architecture
  • Ingest: scheduled read-only jobs pull from Reporting Services (SQL read-only account or SSRS report exports) and the costing workbook (SharePoint / Graph API) into RODBOT's own store.
  • Store: PostgreSQL or SQL Server schema: quotes, mixes, plants, prices, check runs, alerts, step owners, audit log.
  • Engine: rules modules, one per check, each versioned and configurable (tolerances, thresholds, recipients).
  • Output: daily summary email/Teams, alerts to named recipients, web dashboard evolved from Mawsons_Ops_Prototype.html.
Assumed stack [A]
  • Backend: Python 3.12 + FastAPI, scheduled worker (Azure Functions timer or container cron)
  • Frontend: React + TypeScript, ported from the prototype screens
  • Auth: Microsoft Entra ID SSO with roles (Coordinator, Manager, Admin)
  • Hosting: Mawsons Azure tenant (Microsoft shop assumed from SSRS / SharePoint)
  • CI/CD: GitHub Actions or Azure DevOps; IaC in Bicep/Terraform
Engineering rules
  • Read-only DB credentials, enforced in code and by the DB account.
  • Every check run is logged with inputs and result (audit and parallel-run comparison).
  • BDD acceptance criteria per check (task W9-1), tests written before rules logic.
  • Rules are config + tests, not hard-coded: Rod's logic will be corrected in January.
  • Follows Globant SSDLC (security review in W8-1).

9. Risks

  • Rod's logic is unrecoverable before January. Rules in W2/W6 are built from SSRS report definitions and sample outputs, so correctness is proven by parallel run (W2-6), not by interview.
  • No Reporting Services access. W0-4 has a 5-10 day wait and gates all build. Start the request in week 1.
